# 01 交警手势识别 · 算法说明

## 1. 任务定义

路口/路段出现交警指挥时，系统切换为**交警模式**：识别交警的指挥手势，解译出当前允许的
通行方向，并在屏幕上以**单个绿色箭头**指示；FPGA 侧以"屏幕上只出现一个箭头"作为
交警模式的识别特征，联动播报语音提示。

交警模式下，视觉系统负责**手势 → 通行语义**的解译，车辆的横向/纵向控制交由下游执行。

## 2. 支持的手势类别

系统按《道路交通信号（交警手势）》的 8 类标准指挥手势建模，覆盖路口交通指挥的全场景：

| 序号 | 手势 | 含义 | 通行语义 |
|---|---|---|---|
| 0 | 停止信号 | 禁止前方车辆通行 | 停止（保持报警） |
| 1 | 直行信号 | 允许直行 | 直行 |
| 2 | 左转弯信号 | 允许车辆左转弯 | 左转 |
| 3 | 左转弯待转信号 | 左转车辆进入待转区 | 左转（待转） |
| 4 | 右转弯信号 | 允许车辆右转弯 | 右转 |
| 5 | 变道信号 | 允许变更车道 | 左 / 右（按手势侧别） |
| 6 | 减速慢行信号 | 减速通过 | 减速 |
| 7 | 靠边停车信号 | 示意车辆靠边停车 | 靠边停车 |

除上述有效手势外，模型另设 **`other` 拒识类**：画面中出现的交警未作出指挥手势、
或存在行人/车辆/广告牌等干扰目标时，输出 `other`，系统不进入交警模式。

**类别与语义解耦**：分类头输出的是手势类别索引，方向语义由映射表给出
（`CLASS_TO_KIND` / `KIND_TO_DIRECTION`）。多个功能等价的手势可以映射到同一语义
（如"左转弯"与"左转弯待转"都落到左转），因此新增或调整手势不需要改网络结构，
只需更新映射表。本次部署的映射配置覆盖左转、直行两个通行方向与 `other` 拒识。

## 3. 输入契约

板上输入不是原始 BGR 视频帧，而是 FPGA 已完成红绿判定的**单通道 YRG**：

```
0 ~ 253 = 灰度       254 = 纯红       255 = 纯绿
```

RK 端重建三通道 → 96×96 **直接拉伸**（不补黑边；补黑边实测会显著降低置信度）→ RGB
→ NHWC uint8 0..255 送入模型。

**⚠️ 不在 RK 端重做 `fpga_rg_gray()`。** FPGA 已经完成红绿判定，RK 再执行一遍等于用
另一套阈值覆盖 FPGA 的结论，两边阈值不一致时模型看到的是训练中从未出现过的图像，
会造成置信度不可预期地下降。红绿判定保持"单一来源"是这条链路的硬约束。

## 4. 网络结构

轻量化的端到端手势分类网络，面向 RK3568 NPU 部署：

```
Input 96×96×3
  ├─ Conv3×3(3→16)   + BN + ReLU + MaxPool
  ├─ Conv3×3(16→32)  + BN + ReLU + MaxPool
  ├─ Conv3×3(32→64)  + BN + ReLU + MaxPool
  ├─ Conv3×3(64→96)  + BN + ReLU + GlobalAvgPool
  └─ Linear(96 → N)  ,  N = 手势类别数
```

- 参数量 ~200 KB（FP16），单帧推理耗时远低于每轮采集周期，不构成链路瓶颈
- 输入尺寸固定 96×96：手势的关键信息是**肢体构型**而非细节纹理，小分辨率即可保持判别力，
  同时把算力压到最低
- 输出层维度 `N` 与类别集合一致，类别数量由训练配置给定，不写死在网络里

## 5. 训练方法

**输入变换**逐条复刻 FPGA 侧 Verilog `rgb888_yrg` 的判定逻辑，保证训练域与板端输入域一致：

```
RED_MIN = 96          red = (r >= 96) & (r > 2g) & (r > 2b)
GREEN_MIN = 56        grn = (g >= 56) & (g > r + 16) & (g > b + 16)
GREEN_MARGIN = 16
亮度     Y = (77R + 150G + 29B) >> 8     （77 + 150 + 29 = 256，精确加权平均）
命中红/绿处分别覆盖为纯红 / 纯绿哨兵值
```

这套变换的意义：交警的荧光背心、手套、指挥棒在 YRG 域中被稳定映射为纯绿/纯红，
使手势轮廓在灰度背景上获得**与光照无关的高对比度** —— 这是模型在白天、逆光、
隧道口等不同光照下保持稳定的关键。

**数据组织**

- 每个手势类别单独采集视频/图像样本，按帧切分
- 训练/验证按**视频段**切分而非按帧切分，避免同一段视频的相邻帧同时落入训练与验证造成虚高
- `other` 类由非交警场景（普通行车、导航屏、行人、路口空镜）构成，保证拒识能力是
  **独立验证**出来的，而不是训练集里学到的

**训练超参**

| 项 | 值 |
|---|---|
| 输入尺寸 | 96×96 |
| 优化器 | SGD + 余弦退火 |
| epoch | 70 |
| batch | 8 |
| 学习率 | 2e-3 |
| 增强 | 黑边鲁棒（随机上下/左右留边）、亮度抖动 |

## 6. 时序判决

单帧分类结果不直接输出，经**因果多数票 + 连续确认**状态机过滤，抑制偶发误判：

```
每轮喂入 (N,) 原始 logits
  ├─ 若判为 other 或置信度低于该类门槛  →  记一次 miss
  │     └─ 连续 RELEASE_ROUNDS 次 miss  →  退出交警模式，清空票窗
  └─ 若判为有效手势且过门槛  →  票窗追加
        └─ 同一手势连续 LOCK_ROUNDS 轮  →  确认进入交警模式，输出对应箭头
```

**门槛与确认轮数按手势类别分别配置**（`CONF_MIN_BY_KIND` / `LOCK_ROUNDS_BY_KIND`）。
不同手势的类间可分性不同，统一门槛等于用一个类别的最优点去惩罚另一个类别。

当前配置：

| 参数 | 左转 | 直行 | 说明 |
|---|---|---|---|
| `CONF_MIN` | 0.95 | 0.90 | 单帧分类置信度门槛 |
| `LOCK_ROUNDS` | 2 | 2 | 连续确认轮数 |
| `RELEASE_ROUNDS` | 1 | 1 | 连续 miss 即退出 |

选点方法：在整段连续帧上复放（逐帧不抽样），取「有效手势段全程不掉线」与
「非交警场景不误触发」之间的最大余量。

设计要点：

- **因果**：只依赖当轮及此前的结果，不引入未来帧，满足实时在线要求
- **连续确认**：要求同一手势连续多轮一致，散点误检无法累积成一次触发
- **严格连续**：miss 一律清零连击计数，杜绝"隔一轮检出一帧"式的漏网
- **旧票隔离**：连续计数要求"本轮模型原话 == 窗口多数票"，窗口里的历史票
  无法把连续的新证据锁成旧类别（否则方向会反）
- **NaN 防护**：判据写成 `not (conf >= CONF_MIN)` 而非 `conf < CONF_MIN`，
  并让 softmax 在遇到非有限值时退化为均匀分布，防止 NaN 被误判为"过线"

帧率方面，板上约 0.7 s / 轮，`LOCK_ROUNDS=2` 对应约 1.4 s 确认时间，
`RELEASE_ROUNDS=1` 使手势结束后一个采集周期内即可退出，屏幕不会粘连。

## 7. 性能

| 评测项 | 结果 |
|---|---|
| 有效手势逐帧识别（多段连续帧，不抽样） | 99.7% ~ 100% |
| 整段连续帧中的最低置信度 | 0.9597 |
| 非交警场景（官方行车 + 导航素材，3683 帧） | 误触发 **0** 次 |
| 静态截图输入（各手势代表帧） | 0.9994 ~ 0.9999 |
| 端侧模型体积 | 196,909 B |
| 部署精度 | FP16（未量化） |

**为什么用 FP16 而不是 INT8**：本网络输入分辨率低（96×96）、通道数少，
INT8 量化的算力收益可以忽略，但在历史项目中多次出现 INT8 把稀疏/细粒度特征
（如手势指尖、指挥棒角度）压掉的情况，导致类别混淆。FP16 在本模型上
与 FP32 的判决一致率实测 100%，概率偏差 < 2e-4，因此保持 FP16。

## 8. 鲁棒性设计

1. **黑边鲁棒**：训练阶段随机在图像四周施加黑边（模拟播放器截图、裁剪不一致等场景），
   使模型对画面有效区域的比例变化不敏感。实测有效区域占比 33% / 50% 时仍保持判决正确。
2. **宽高比鲁棒**：板上输入为 16:9 直接拉伸，训练时混合多种宽高比样本，
   避免模型依赖固定比例。
3. **光照鲁棒**：所有样本统一走 FPGA YRG 变换，背心/手套的高对比度映射天然消除了
   光照强度差异。
4. **拒绝能力**：`other` 类与非交警场景的独立验证集上误触发为 0，配合连续确认机制，
   普通驾驶画面不会误进交警模式。
