# 03 红绿灯灯箱检测 · 算法说明

## 1. 任务定义

**只做一件事：找出画面里的灯箱，并读出灯箱里的颜色（红 / 绿 / 未亮）。**

- 颜色判据**不在模型里**，在 `traffic_rules` 里：FPGA 已经把真红编码成 254、真绿编码成 255，
  模型只需要给出灯箱框，判色是在单通道 YRG 上数 254/255 —— 精确、零阈值。
- 方向语义由**下游数框**决定，不是模型输出的：

```
1 个灯箱 → 圆盘灯，全方向
2 个灯箱 → 左转 + 直行
3 个灯箱 → 左转 + 直行 + 右转
```

赛题原文只要求「红/绿识别 + 报警」，方向是下游几何推出来的，模型不承担方向任务。

## 2. 输入契约

```
FPGA 单通道 YRG (720×1280)
  → 254 还原纯红 / 255 还原纯绿 / 其余灰度
  → DIRECT 1280×768 直接拉伸（⚠️ 而非常见的 1280×720，高度是 768）
  → float32 NHWC 0..255
```

## 3. 训练数据：纯红绿灰度域（v2 的关键改动）

**v1 的训练图里有一半是 `to_gray()` 生成的全灰度副本** —— 那是训练框里根本不会出现的
干扰域。v2 整个删掉，训练集 100% 是 FPGA 输出的红绿灰度图（红=254 / 绿=255 哨兵值）。

| 版本 | 训练域 | mAP50 | conf 0.20 召回 / 精确 | 误检 |
|---|---|---|---|---|
| v1 | 红绿灰度 + 全灰度混 | — | — | 10 |
| **v2** | **纯红绿灰度** | **0.954** | **95.5% / 95.5%** | **3** |

> 教训：换输入形式后某类指标暴跌，先做 2×2 交叉（旧模型喂新输入），
> 别从"输入变了"直接倒推病因。

## 4. 训练

```bash
python train_housing_rg.py n1280     # yolov8n, imgsz=1280, batch=8
python train_housing_rg.py n1408     # 备选
python train_housing_rg.py s1280     # yolov8s, batch=4
```

`rect=True` —— 16:9 批次不再补成正方形；`workers=0` —— Windows 共享内存会炸；
`amp=False` —— Blackwell 分配器的 INTERNAL ASSERT。

数据增强：`degrees=2, translate=0.15, scale=0.7, shear=1, perspective=0.0003,
fliplr=0.5, hsv_h/s/v = 0.015/0.7/0.5, mosaic=1.0, erasing=0.2`。

⚠️ 数据构建脚本**不给负样本生成灰度副本**，负样本本身就是红绿域。

## 5. 导出

```bash
python split_onnx.py housing.onnx housing_split.onnx 1   # 必须拆 Concat
python conv_housing_fp16.py housing_split.onnx <outdir>  # FP16，双平台
```

**必须拆 Concat**：不拆的话框坐标与置信度共用同一个量化 scale，
scale 被框坐标主导（量级差 7 万倍），置信度全被压成 0。

**必须 FP16 不用 INT8**：小目标单类检测，INT8 会把小框的定位打散。
转为 `housing_3568_fp16.rknn`（8.2 MB，sha `bc5d9a90…`），精确度 86.5% → **94.1%**。

## 6. 下游框过滤（`traffic_boxes.py`，V27）

灯箱模型只回答"哪里有像灯箱的东西"，会稳定交出三类误检：倒计时数字、限速牌、
尾灯/钩形鬼影。一块假框进入 `traffic_rules.judge()` 就会占用方向位，让同组真灯
**整体错位** —— 这是"红绿灯乱跳"的直接来源。

**判据（V27 终极版）**

1. **滑动窗口颜色集中度**：沿长边用 1/3 宽的窗口**滑动**，找纯红/纯绿的最大集中度，
   ≥ `SHARE_MIN(0.70)` 才算真灯。红绿**分开**算 —— 横排灯箱同时亮左转红 + 直行绿时，
   合并会把两种颜色摊到两格，误杀真灯。
2. **纵向高度统计**：按 `cy/H` 归行，行内 `h` 明显小于中位的判为陪衬，离行心太远的判为离群。
   行内不足 `ROW_MIN_ITEMS` 个框时整行跳过 —— 没有参照就不判断。

> ⚠️ 窗口必须能**滑动**，不能死钉在三等分边界上。板端 38 框实测：
> 固定 @0.70 真灯只剩 28/38，可滑动是 37/38。

> ⚠️ 这套判据**只在真灰度帧上用**。二值帧取值塌缩成 {0,253}，没有 254/255，所有框会被判成 unlit。

## 7. 已知局限

1. **中国场景数据稀缺**：有箭头形状的数据集仅 433 张且 100% 竖排灯，而比赛是横排灯。
   方向判定属于**数据缺口，不是调参问题**，所以模型只做"灯箱 + 颜色"，方向交给下游数框。
2. **交叉场景要靠门控**：树叶、红色车身等会干扰红绿判定，需要 V13 那一级的门控兜底。
3. **竖排/横排灯制差异**：训练集 43% 文件全竖排而验证集 100% 横排，几何规则
   （如长宽比 `MIN_ASPECT=1.15`）会拒掉 96.5% 的真灯 —— 不要加死板的形状门。
